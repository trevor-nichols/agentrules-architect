# Provider model and API audit — 2026-10-23

This is a read-only review of the text and tool-using models used by AgentRules' analysis pipeline. It compares the current preset registry, request builders, capability checks, and lifecycle guide with official provider documentation as of 2026-10-23. The recommendations below are **proposed changes**, not implemented or live-tested changes. Account, region, and quota availability still require provider-specific live smoke tests.

## Recommended order

| Priority | Work | Reason |
| --- | --- | --- |
| P0 | Correct DeepSeek Flash routing and Gemini 2.5 lifecycle claims | DeepSeek's old Flash wire ID is a temporary alias for V4.1 Flash; the repository's stated Gemini 2.5 shutdown date has passed and is contradicted by Google's current schedule. |
| P0 | Repair OpenAI model limit selection and Gemini function-call continuation | The OpenAI limit heuristic can pack beyond documented input limits; the Gemini researcher loop discards the call identity and thought state needed for a valid function response. |
| P1 | Add current direct API models with explicit capability profiles | New IDs need correct reasoning, thinking, context, output, tool, and refusal contracts before they appear in the picker. |
| P1 | Update deprecation metadata and saved-key routing | Existing selections must remain readable; deprecated-but-live endpoints should not silently change model or cost before shutdown. |
| P2 | Evaluate transport and SDK migrations | xAI recommends Responses; Anthropic has a new API version; Gemini Argon recommends a newer SDK. These require separate contract tests and rollout decisions. |

## Direct API models

### OpenAI

**Add after request capability work:** `gpt-6-astra`, `gpt-6.1-sol`, and `gpt-6-luna` as distinct tiers. Add `gpt-6-sol` if adopting OpenAI's exact documented replacement for deprecated `gpt-5.3-codex` and `gpt-5.1`. All four use the Responses API and have 1,050,000 total context, 922,000 maximum input, and 128,000 maximum output. Astra and 6.1 Sol allow `low`, `medium`, `high`, `xhigh`, and `max`; 6 Sol and Luna also allow `none`. Keep the current GPT-5.6 presets as explicit rollback choices until new defaults are evaluated. The [model catalog](https://developers.openai.com/api/docs/models) and [GPT-6.1 Sol model card](https://developers.openai.com/api/docs/models/gpt-6.1-sol) define the current IDs and limits.

**Mark deprecated, preserving saved behavior until shutdown:** GPT-5 and o3 presets (December 11, 2026), GPT-4.1 presets (January 14, 2027), and GPT-5.1, GPT-5.3-Codex, and GPT-5.4 Nano presets (April 1, 2027). Use the [OpenAI deprecations](https://developers.openai.com/api/docs/deprecations) replacement targets. Do not equate “older” with “deprecated”: other registered models need an explicit notice before being hidden. `OpenAIArchitect` still defaults to `o3` in `src/agentrules/core/agents/openai/architect.py:45` and `compat.py:17`; switch that constructor default before its shutdown.

**Fix the request and packing contract first:** `src/agentrules/core/agents/openai/request_builder.py` has no GPT-6 capability rows; its unknown-model path can reduce `xhigh` or `max` to `high` and does not reject unsupported `none` for Astra or 6.1 Sol. `src/agentrules/config/agents.py:221-233` assigns a broad 400,000 input limit to GPT-5.4 Mini/Nano and GPT-5.3-Codex, whose documented maximum input is 272,000. It also caps GPT-5.5 and GPT-4.1 well below their current documented limits. Replace the name-substring limit heuristic with per-model metadata and test the effective input limit and wire effort for each family. See the [GPT-5.4 Mini](https://developers.openai.com/api/docs/models/gpt-5.4-mini), [GPT-5.5](https://developers.openai.com/api/docs/models/gpt-5.5), and [GPT-4.1](https://developers.openai.com/api/docs/models/gpt-4.1) model cards.

**API:** The current Responses endpoint remains appropriate; no mandatory endpoint switch was found. The synchronous SDK call inside `OpenAIArchitect.analyze` should move off the asyncio event loop as a separate client-plumbing fix. Codex is covered under runtime providers below.

### DeepSeek

**Add canonical Flash:** expose `deepseek-flash` for V4.1 Flash, currently serving the 1017 update. The four existing `deepseek-v4-flash*` preset keys should become compatibility IDs routed to equivalent `deepseek-flash` thinking/effort presets. The upstream `deepseek-v4-flash` wire name still works only as a temporary redirect to the new model. Keep `deepseek-v4-pro`; DeepSeek explicitly continued its service. Update `DeepSeekArchitect`'s direct default, model defaults, typed model configurations, labels, and lifecycle guide. DeepSeek lists the current wire IDs, 1M context, and 384K maximum output in [Models & Pricing](https://api-docs.deepseek.com/quick_start/pricing/), and explains the Flash transition in its [change log](https://api-docs.deepseek.com/updates/). AgentRules' 32K output cap may remain an explicit application limit.

**Preserve legacy keys:** `deepseek-chat` and `deepseek-reasoner` must route **directly** to the new canonical non-thinking and thinking/high keys. `resolve_runtime_preset_key` in `src/agentrules/core/configuration/model_presets.py:258-287` performs one replacement step, so routing them via a deprecated V4 Flash key would leave an obsolete intermediate selection. Match their direct-constructor aliases in `src/agentrules/core/agents/deepseek/config.py:53-69`.

**API:** The current OpenAI-compatible Chat Completions endpoint remains documented for text, JSON mode, thinking control, and tool calls. The existing `extra_body.thinking.type` and `reasoning_effort` shape matches the [thinking guide](https://api-docs.deepseek.com/guides/thinking_mode/). V4.1 Flash adds [native image input](https://api-docs.deepseek.com/guides/vision/), but the current text-only analysis pipeline does not need a vision preset or Files API integration. DeepSeek also launched Search and Fetch APIs; these are optional new tools, not a prerequisite for the model refresh.

### Anthropic

**Add with model-specific contracts:** `claude-opus-5-5`, `claude-sonnet-5-5`, `claude-haiku-5-5`, and `claude-fable-5-1` are current direct API candidates. Each has a 1M context and 128K maximum output and supports structured output. Opus 5.5 and Fable 5.1 always use adaptive thinking. Sonnet 5.5 rejects `thinking.disabled`; its `between_tools` option is distinct from disabled thinking. Haiku 5.5 permits disabled thinking only at low, medium, or high effort. All four can return a 200 response with a refusal stop reason, so extend the existing typed refusal and stream-buffering path rather than treating a partial stream as success. Fable 5.1 requires 30-day retention and is not an ordinary zero-data-retention choice. See the [model overview](https://platform.claude.com/docs/en/models/overview), [thinking controls](https://platform.claude.com/docs/en/build-with-claude/thinking), [refusal behavior](https://platform.claude.com/docs/en/build-with-claude/refusals-and-fallback), and [retention policy](https://platform.claude.com/docs/en/manage-claude/api-and-data-retention). Do not add restricted Mythos 5.1 to a general picker.

**Mark Sonnet 4.5 compatibility keys deprecated:** `claude-sonnet` and `claude-sonnet-reasoning` remain bound to Sonnet 4.5 today; the [Anthropic deprecation schedule](https://platform.claude.com/docs/en/about-claude/model-deprecations) gives November 30, 2026 as retirement. Hide them from new selection, retain existing behavior until retirement, then redirect saved keys to an explicitly selected Sonnet 5.5 profile. Haiku 4.5 and older Opus 4.x models must not be called retired merely because a newer model exists. Fix stale “Latest” labels and the retired Claude 3.5 Sonnet ID in `src/agentrules/config/prompts/final_analysis_prompt.py:207`.

**API:** Anthropic's [2026-10-21 API migration](https://platform.claude.com/docs/en/api/migration-2026-10-21) is a separate SDK/client review. SDK 2.x changes the default API version, authentication header, and some parameter validation. The current plain user-text request does not use the newly disallowed sampling or document-block shapes, but gateway/auth behavior and the `output_config` compatibility shim need tests before raising the SDK floor. The synchronous direct SDK call inside `AnthropicArchitect.analyze` should also leave the event loop.

### xAI

**Add `grok-4.7`:** the current flagship has 500K context, supports function calling and structured output, and accepts `low`, `medium`, `high` (default), and `xhigh`; reasoning cannot be disabled. Add four effort presets and a strict capability profile. Reclassify 4.6 as a fallback without treating it as retired. Keep the 4.20 pinned variants, 4.3, and Grok Build choices unless xAI announces retirement. Grok 4.7 Fast is **not** available on the public xAI API and should not be a preset. See the [Grok 4.7 model page](https://docs.x.ai/developers/models/grok-4.7), [reasoning controls](https://docs.x.ai/developers/model-capabilities/text/reasoning), and [Grok 4.7 developer guide](https://docs.x.ai/developers/grok-4-7).

**API:** xAI calls Chat Completions a [legacy/deprecated endpoint](https://docs.x.ai/developers/model-capabilities/text/comparison), although its [Chat Completions guide](https://docs.x.ai/developers/model-capabilities/legacy/chat-completions) still shows `grok-4.7` working there. Adding the model does not require an immediate transport migration. Plan a separate move to Responses to gain the supported reasoning state and future server-side tools; that needs request, stream, tool, and response-parser contract changes. For now, the existing adapter's `grok-4.7` support should be validated with an opt-in live smoke.

### Google Gemini

**Add `gemini-3.8-flash` and `gemini-4-argon`:** both accept low, medium, and high thinking, with no minimal or disabled mode. Flash has a 1,048,576-token input limit and 65,536 maximum output. Argon's 1,048,576 window is shared by input, thinking, and output; its ordinary synchronous request caps at 32,768 output tokens, while newer SDK continuation can generate beyond a single request. Record those differences in capability metadata and packing. See the [Gemini 3.8 Flash model card](https://ai.google.dev/gemini-api/docs/models/gemini-3.8-flash), [Gemini 4 Argon model card](https://ai.google.dev/gemini-api/docs/models/gemini-4-argon), and [Argon GenerateContent guide](https://ai.google.dev/gemini-api/docs/generate-content/latest-model).

**Correct active aliases and dates:** Google's [current deprecation schedule](https://ai.google.dev/gemini-api/docs/deprecations) says `gemini-3.7-flash` API calls automatically route to 3.8, and `gemini-3.5-flash` calls route to 3.6. Preserve saved keys but disclose the effective model. It also says Gemini 2.5 Flash and Pro are **not deprecated**, have no announced shutdown date, and continue to serve prior users; new-user access is limited. Remove the October 16, 2026 shutdown claims in `src/agentrules/config/agents.py:433-456`, `docs/provider-model-lifecycle.md:152-154`, and `README.md:313`. The already-retired 3 Pro and 3.1 Flash-Lite preview redirects remain valid.

**API and SDK:** `pyproject.toml` allows `google-genai>=1.56.0`, while `uv.lock` currently resolves 1.64.0. Google's [Argon guide](https://ai.google.dev/gemini-api/docs/generate-content/latest-model) specifies Python SDK 2.30.1 or newer for automatic continuation. Raise the floor and regenerate the lockfile when onboarding Argon, then check `typings/google/genai/types.pyi`. The existing `models.generate_content` path still works; the [Interactions API](https://ai.google.dev/gemini-api/docs/interactions-overview) is a separate design choice. More urgently, the researcher loop in `src/agentrules/core/analysis/phase_1.py:294-334` sends tool feedback as a fresh text prompt, and `src/agentrules/core/agents/gemini/response_parser.py:68-77` discards function-call IDs. Preserve the model content, thought signatures, and matching function-call ID/name in the next turn before enabling 3.8/4 for researcher tool use. Google's [Gemini 3.5 changes](https://ai.google.dev/gemini-api/docs/generate-content/whats-new-gemini-3.5) and [3.8 migration guide](https://ai.google.dev/gemini-api/docs/generate-content/whats-new-gemini-3.8) describe that contract.

## Local runtime providers

**Codex:** keep account-specific `model/list` discovery in `src/agentrules/core/agents/codex/client.py` and `model_selection.py`; do not add static GPT-6 Codex preset IDs. The current model/effort and `outputSchema` request paths match the [app-server documentation](https://learn.chatgpt.com/docs/app-server). Direct OpenAI API deprecations do not prove runtime availability.

**Claude Code:** keep the moving `best`, `opus`, `sonnet`, and `fable` runtime aliases, and add `haiku` if useful in the picker. Add pinned 5.5/5.1 choices only with **exact resolved executable** version gates: Fable 5.1 ≥2.1.257, Opus 5.5 ≥2.1.280, Sonnet 5.5 ≥2.1.284, Haiku 5.5 ≥2.1.293. The prefix matcher in `src/agentrules/core/configuration/services/claude_code.py` must check longer, more specific IDs before older `*-5` prefixes. The current lockfile's Claude Agent SDK 0.2.119 bundles Claude Code 2.1.210, below all four minima; an SDK/lockfile update is needed before the pinned choices can work in a fresh install. See [Claude Code model configuration](https://code.claude.com/docs/en/model-config) and the [Claude Agent SDK release](https://github.com/anthropics/claude-agent-sdk-python/releases/tag/v0.2.165) that bundles 2.1.294.

## Implementation and verification checkpoints

1. Make lifecycle corrections and add one-hop saved-key redirects; verify old config files retain their keys while runtime selection resolves to the intended live model. Do not redirect deprecated-but-live OpenAI or Anthropic keys early.
2. Add immutable capability metadata and provider-contract tests for every new model: effort/thinking, tool compatibility, structured output, output cap, and effective input limit. Reject unsupported combinations before network dispatch.
3. Repair the Gemini tool continuation path; test a complete two-turn function-call exchange with ID and thought-signature preservation before making new Gemini models available to the researcher role.
4. Update SDK floors and `uv.lock` only alongside the relevant provider contract tests. Run import smoke, ruff, pyright, focused provider tests, and the opt-in live provider smoke with credentials available to the operator.
5. Evaluate changing defaults on representative AgentRules projects. A newer model ID alone is not evidence of better task quality, cost, or availability for this pipeline.

This audit used repository inspection and official documentation. It did not call paid provider APIs, test account entitlement, or alter runtime model settings.
